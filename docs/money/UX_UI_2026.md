# Money UX/UI 2026 — provider and admin

## Principles
Mobile-first, progressive disclosure, WCAG 2.2 AA, EN/AR parity and real RTL. Financial state is explicit and never communicated by color alone. Server state is authoritative; optimistic UI may improve responsiveness but cannot imply payment success or entitlement grant before confirmation.

## Provider information architecture
Plan discovery → plan comparison → billing interval → payment method → payment instructions/checkout → processing/review → result → My Plan.

Plan cards show name, exact localized price/currency, monthly/annual interval, included capabilities and limits. The recommended treatment is admin-configurable content, not a hard-coded VIP visual hierarchy. A sticky mobile CTA appears only after a valid selection.

Manual rails (Sham Cash/Syriatel Cash): show the server-provided QR/instructions, expected amount/currency and expiring payment reference; upload receipt in a separate evidence step; then show Pending review with reference and timeline. Never say Paid until an authorized review commits.

Cash office: list admin-enabled offices with address, opening information and instructions; the payment intent/reference remains visible for staff matching.

Stripe: hosted/approved checkout surface; return screen says Processing until authoritative webhook confirmation is observed.

My Plan: current plan, status, start/end, localized price, usage meters, entitlement list, payment history and renew/upgrade entry points. Expiry messaging is staged and non-alarming.

## Admin information architecture
Settings / Plans: plan list, draft version editor, price per interval/currency, entitlement matrix, publish/retire, coupon management. Published versions are read-only.

Payments: Pending review / Approved / Rejected / Failed / All. Review detail shows provider, expected amount/currency, method, payment reference, restricted receipt derivative, duplicate/risk signals, previous attempts and immutable audit timeline. Approve/reject actions require explicit confirmation and reason where policy requires it.

## Interaction/accessibility acceptance
Target widths: 320, 390, 430, 768, 1024, 1440. Keyboard-complete desktop paths, visible focus, 44px touch targets where practical, semantic headings/labels, status text plus icon, no horizontal overflow, reduced-motion support, localized currency via Intl, and mirrored directional controls in RTL where semantics require it.

## Security UX
Never expose storage keys, provider secrets, Stripe secrets, raw risk-engine internals or unrestricted receipt URLs. Evidence downloads/previews use audited short-lived authorization. UI does not make fraud claims from image heuristics; it presents review signals with provenance.
