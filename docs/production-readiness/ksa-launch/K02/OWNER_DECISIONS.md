## A. Decisions K02 implements (confirmation requested)

| ID    | Decision                    | What the code now does                                                                                                                                                                                                                                                                                                                                        | Confirm |
| ----- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| K02-1 | Currency and unit (R18 D-2) | New bids/bookings are SAR in integer **halalas** (`amountScale = 2`). The server assigns the currency; any other currency is refused (400 `CURRENCY_NOT_APPROVED`). Decimal input is converted once, exactly; more than 2 decimals is refused, never rounded.                                                                                                 | ☐       |
| K02-2 | Legacy amounts              | Pre-K02 rows keep their stored integer and currency, get `amountScale = NULL` (LEGACY_UNVERIFIED), are shown with an "unverified" label, and are excluded from every total and counted instead. **No bulk ×100 / ÷100.**                                                                                                                                      | ☐       |
| K02-3 | Fixed vs hourly             | A provider chooses FIXED (default) or HOURLY. Only FIXED amounts are summed as booked value; hourly rates are shown "/hr" and counted, never summed.                                                                                                                                                                                                          | ☐       |
| K02-4 | Payable scope               | Booking amounts are **booked value, not money held**. The wallet/admin show no fee, net or "available balance" (`feeStatus: NOT_APPROVED`). Withdrawals stay disabled (R16 D-1).                                                                                                                                                                              | ☐       |
| K02-5 | Launch market               | One market: SA, timezone Asia/Riyadh, written by the audited operator CLI `market:init:ksa` (not the dev seed). Schedules are entered and displayed in Riyadh time.                                                                                                                                                                                           | ☐       |
| K02-6 | Policy acceptance           | Signup records the exact Terms/Privacy **version** with the **server's** time; stale versions are refused (409). Legacy accounts are never backfilled. Production requires both APPROVED releases with new version IDs and nonblank approval references. Explicitly labelled staging permits draft rehearsal only with `LEGAL_DRAFT_ACCEPTANCE_ALLOWED=true`. | ☐       |
| K02-7 | Brand (provisional)         | One name everywhere: **FixNow / فيكس ناو** (already the app's `appName`). "Maharah" and "On-Demand Home Services Marketplace" were removed from public surfaces.                                                                                                                                                                                              | ☐       |

## B. Proposed (recommendations, not approved)

| ID   | Topic                       | Recommendation                                                                                                                                                                                                                                                                                                                                    | Why                                                                                                                                                                       |
| ---- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P-1  | Collection model            | **Subscription-only collection** for launch: providers pay plans through a licensed PSP; the platform never holds booking funds; no escrow, no payouts.                                                                                                                                                                                           | Matches the implemented subscription model (R29–R33). Holding/pooling third-party funds is a SAMA-licensable payment activity (see notes §7).                             |
| P-2  | Platform fee                | None at launch (`PROVIDER_PLATFORM_FEE_BPS` no longer feeds any figure).                                                                                                                                                                                                                                                                          | No fee is approved (R16 P10); nothing is collected from bookings.                                                                                                         |
| P-3  | First city / categories     | Riyadh first; categories = the six seeded leaf categories (plumbing, electrical, AC repair, cleaning, …) after owner review of the Arabic labels.                                                                                                                                                                                                 | The market registry already contains SA; matching uses free-text `serviceAreaCity` + `cityKey` (see memory: place catalogue unseeded).                                    |
| P-4  | Phone behaviour             | Collect provider phone in E.164 (`+9665XXXXXXXX`), accept Arabic-Indic digits and `00` prefix, store normalised, label **"not verified"**; **no SMS promise** until an approved sender ID/transport and a delivery test exist.                                                                                                                    | No SMS transport exists; OTP is email-only.                                                                                                                               |
| P-5  | Location                    | Opt-in geolocation with manual address fallback (exists). Seeker requests are not yet checked against the market envelope — propose adding a server check before launch (K03+).                                                                                                                                                                   | Providers outside SA are refused by the work-area policy; seekers are not.                                                                                                |
| P-6  | Identity verification basis | Do **not** store copies of national ID / Iqama unless a statute requires it. Proposed minimal alternative: verify through an approved government digital-identity service (to be identified and confirmed by counsel) or an operator **visual check without retaining a copy**, storing only the verification outcome, method, reviewer and date. | PDPL Art. 28 / IR Art. 31 forbid copying official identity documents except where a statute requires it or a competent public entity requests it; consent is not a basis. |
| P-7  | Policy change notice        | Publish material Terms changes **≥ 7 days** before effect and require re-acceptance through the existing version mechanism.                                                                                                                                                                                                                       | E-Commerce IR Art. 18 (intermediary platforms).                                                                                                                           |
| P-8  | Privacy-rights handling     | In-app request channel (Help ticket category "Privacy request"), identity re-verification, 30-day response (extendable once by 30 with notice), audited.                                                                                                                                                                                          | PDPL IR Art. 3(1).                                                                                                                                                        |
| P-9  | Hosting region              | Prefer in-Kingdom hosting; if outside KSA, perform the PDPL transfer risk assessment and adopt SDAIA standard contractual clauses with each processor.                                                                                                                                                                                            | PDPL Art. 29 + Transfer Regulation Arts. 4, 7.                                                                                                                            |
| P-10 | Domain                      | Register a `.com.sa` (needs CR) and the matching `.السعودية`; serve the web on the `.sa` domain.                                                                                                                                                                                                                                                  | SaudiNIC regulation v5.0 cl. 4-3-2.                                                                                                                                       |

## D. How an approval lands in code

1. Legal texts: edit `apps/web/src/app/features/legal/copy/legal-documents.copy.ts`
   (both languages), give each changed document a **new** version id in
   `packages/contracts/src/iam/legal/legal-documents.ts` and the copy file,
   set `status: 'APPROVED'` and `approvalReference`. Tests fail if the two
   disagree. Publish ≥ 7 days ahead (P-7).
2. Currency/scale changes: `APPROVED_CURRENCY_SCALES` and the DB CHECK
   constraints change together in one reviewed migration.
3. Market: run `market:init:ksa` (see `IMPLEMENTATION.md` §Operator).
