## Durable acceptance gate

`node scripts/security/dependency-audit.cjs` runs a real full-tree `pnpm audit`
and writes the unmodified registry JSON. `--prod` runs the production scope.
The runner requires all five severity counters, a nonempty dependency inventory,
an empty advisory map, no muted findings, and a successful process exit.
Timeouts, unavailable registries, malformed JSON, unknown/incomplete schemas and
nonzero command exit status all fail closed. Configured audit exceptions are
rejected, not silently honored. The CI job uploads both reports even on failure.

The two audit steps live inside the existing `security-scan` job, which the
existing final `CI gate` already requires. No branch-protection setting was
changed; administrators must still enforce required checks at the repository
level. This does not claim that merely adding a job turns branch protection on.

New policy tests cover every severity, inconsistent counters/maps, malformed and
missing responses, process failure, timeout, scope arguments and config
exceptions. They do not exploit application servers or process dangerous
archive fixtures. Their initial local run: **39 passed, 0 failed, 0 skipped**.

Commands:

```sh
pnpm install --frozen-lockfile
pnpm security:audit:test
pnpm security:audit
pnpm security:audit:prod
```

Inspect overrides when the owning upstream package adopts these fixes. Remove
an override only when the resolved lockfile and full audit demonstrate the fix
without it; do not replace it with an ignored-advisory entry.

## Limits and rollback

No migration or production deployment is involved. Reverting the dependency
commit would reintroduce known advisories and is not an acceptable release
state; use a reviewed alternative patch if compatibility requires recovery.
Do not disable the audit gate to make a rollback green.

Dependency advisories are distinct from linter warnings, deprecated-package
notices, peer compatibility notices, runtime lifecycle support, live scanner
acceptance, and full application penetration testing. Existing non-advisory
warnings must remain visible and be reported separately; they are not renamed
as fixed vulnerabilities. This work does not authorize merging or deployment.
